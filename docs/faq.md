# Frequently Asked Questions

## What counts as a Skill?

A documented, reusable workflow, prompt pattern, or piece of automation that helps someone reliably complete a recurring task. If it only makes sense in the context of one project or one week, it is probably not ready to be a Skill yet.

## Which category should my Skill go in?

Pick the closest match among the existing folders under `skills/`. If a Skill genuinely spans two categories, place it in the one that reflects its primary output and cross-link from the other category's README if helpful. Propose a new top-level category only if none of the existing ones fit at all, and raise it as an issue first.

## Can I submit a Skill without a script?

Yes. Many valuable Skills are pure documentation, such as a review checklist or an escalation process. The `scripts/` folder is optional.

## How long does review take?

This varies by category and maintainer availability. If a pull request has not received a response within a reasonable time, it is fine to politely ping the relevant maintainer listed in [`.github/CODEOWNERS`](../.github/CODEOWNERS).

## Can I use a Skill from this repository outside the organization?

This repository is licensed under the [MIT License](../LICENSE), so the general terms of that license apply. Check whether an individual Skill references internal-only tools or data before reusing it externally.

## What if I disagree with a review comment?

Discuss it on the pull request. Maintainers are trying to keep the library consistent and reliable, not to gatekeep unnecessarily; most disagreements resolve with a short conversation. See the [Code of Conduct](../CODE_OF_CONDUCT.md) for how we expect that conversation to go.

## Where do I ask something not covered here?

Open a GitHub Discussion, or an issue labeled "question" if Discussions are not enabled for this repository.
